# FloatNote macOS App

## Build & Deploy
After ANY code change, run `./build.sh` to rebuild and update the app in `/Applications/FloatNote.app`.

Do NOT just run `swift build` — the app bundle in /Applications must be updated too.

**GOTCHA — build.sh's relaunch can silently no-op from sandboxed shells (e.g. Claude Code):** its `pkill` may be blocked, and `open` then just re-focuses the STALE running instance — the new binary never loads. Reliable relaunch: `osascript -e 'tell application "FloatNote" to quit'; sleep 1; open /Applications/FloatNote.app`. When in doubt, compare binary mtime (`stat -f %m /Applications/FloatNote.app/Contents/MacOS/FloatNote`) against the process start time (`ps -o lstart= -p $(pgrep -f FloatNote.app/Contents/MacOS)`).

## Code Signing & Permissions (macOS TCC)
- `build.sh` signs `/Applications/FloatNote.app` with the self-signed **"FloatNote Dev"** identity when present (else ad-hoc). A *stable* identity is what keeps macOS TCC grants (Screen Recording, Microphone) across rebuilds — **ad-hoc pins the cdhash**, so every rebuild changed it and macOS re-prompted. Create the cert once per machine with `docs/dev-signing-cert.sh` (self-signed, codeSigning EKU, in a dedicated `floatnote-dev` keychain).
- The cert is self-signed → **untrusted** (`CSSMERR_TP_NOT_TRUSTED`). So `build.sh` matches it with `security find-identity` **WITHOUT `-v`** (the "valid-only" filter drops untrusted certs — do NOT add it back) and signs **WITHOUT `--options runtime`** (the app has no hardened-runtime entitlements; unneeded for TCC). OS/Gatekeeper trust is irrelevant here — TCC keys on the designated requirement `identifier "com.floatnote.app" and certificate leaf = H"…"`, which stays constant across rebuilds.
- **GOTCHA — changing the signing identity invalidates existing TCC grants.** On the first switch (ad-hoc → FloatNote Dev) the old Mic/Screen grants no longer match and recording *silently no-ops* (record button "does nothing"). Reset the stale entries, then grant once: `tccutil reset Microphone com.floatnote.app && tccutil reset ScreenCapture com.floatnote.app`. Screen Recording needs an app **relaunch** to take effect. After that it persists across all future rebuilds.
- **Recording permission flow / debugging**: `dbg()` writes to `~/.floatnote-debug.log` (no os_log/Console; timestamps are UTC) — first place to look for recording issues. `RecordingManager.checkAndRequestPermissions()` checks **only Microphone**; system audio (Screen Recording) is requested implicitly by `SCShareableContent` and **fails silently** in a `catch → dbg` with error `-3801` → mic-only fallback (`merged=false`). Both permissions granted → `merged=true`.

- Version constant `APP_VERSION` is at the top of `App.swift` — bump it on each update
- Displayed in the status bar (bottom right)

## Key Details
- Fully local-only app (no cloud sync)
- Data stored at `~/.floatnote-local.html`, `~/.floatnote-tabs.json`, `~/.floatnote-folders.json`
- Recordings live in `~/.floatnote-recordings/`
- App settings persist in UserDefaults domain `com.floatnote.app` (all keys `fn.*`) — inspect with `defaults read com.floatnote.app`
- Excalidraw boards live in `~/.floatnote-excalidraw/<noteUUID>.excalidraw.json` (one per note)

## External File Sync (MCP)
- A 2-second polling timer in `AppDelegate` calls both `checkExternalTabChanges()` and `checkExternalFolderChanges()` so MCP-driven edits to `~/.floatnote-tabs.json` / `~/.floatnote-folders.json` show up in the UI without an app restart.
- Both `saveTabsLocal` and `saveFoldersLocal` capture the mod-date *after* writing so the watcher doesn't treat the app's own write as a foreign edit.
- If you add a new on-disk store, follow the same pattern: `lastXModDate` field + `checkExternalXChanges()` + capture-on-save + register in the timer.

## Excalidraw Boards
- Each note has its own Excalidraw whiteboard. The toolbar board button (`pencil.and.outline`, in `FormatToolbar`) toggles `vm.isBoardVisible`, which swaps `ExcalidrawBoardView` in for `RichTextEditor` in `EditorView.content`.
- Button has three states: gray = no diagram, **green** (`Tokens.SUI.boardHasContent`) = board has drawings but is closed, accent/blue + filled bg = board open. "Has content" is driven by `vm.boardContentIds` (seeded at launch via `ExcalidrawStore.scanContentIds()`, updated on each save via the `.floatnoteBoardSaved` notification).
- **The open/closed view is per note and persists**: `NoteTab.isBoardOpen` (⇄ `TabData.isBoardOpen` in `~/.floatnote-tabs.json`, absent = false) is written by `vm.persistBoardVisibility()` on every toggle and on the MCP auto-open path, and restored in `switchTab` and at launch. A note that is really a diagram reopens as one. `addTab` still starts on the editor.
- Storage: `ExcalidrawStore` (in `Excalidraw.swift`) reads/writes `~/.floatnote-excalidraw/<noteUUID>.excalidraw.json` with atomic temp+replace. Hard-delete / empty-trash deletes the board file; trashing keeps it.
- **MCP board access**: `draw_on_board` (simplified shapes → valid Excalidraw elements, modes `replace`/`add` with overlap auto-shift) and `read_board` (element summary) in `mcp-server.js`. Board files follow the External File Sync pattern: `lastBoardModDates` + `checkExternalBoardChanges()` (registered in the AppDelegate timer), capture-on-save inside the `.floatnoteBoardSaved` observer. A foreign change to the **active** note's board auto-opens the board view, or posts `.floatnoteBoardExternallyChanged` to reload it in place when already open. The server uppercases note UUIDs in board filenames to match Swift's `uuidString`. Spec: `docs/superpowers/specs/2026-06-12-mcp-excalidraw-boards-design.md`.
- **Excalidraw runs fully offline in a `WKWebView`.** Excalidraw 0.18 ships ESM with ~25 external npm deps (no UMD), so it MUST be bundled. `vendor/excalidraw/` (entry `main.jsx`, `build.mjs`) uses esbuild to produce a single self-contained `bundle.js` + `index.css` + `fonts/` into `FloatNote/FloatNote/Resources/excalidraw/`. Run `./vendor-excalidraw.sh` once and on Excalidraw upgrades — `./build.sh` does NOT re-vendor, it only copies the static assets.
- The JS↔Swift bridge: page posts `{type:"ready"}` / `{type:"save",...}` to `webkit.messageHandlers.floatnote`; Swift calls `window.floatnoteLoadScene(<json>)` / `floatnoteSetTheme(...)` / `floatnoteFlush()`. A note's saved JSON is injected directly as a JS object literal (valid JSON = valid JS).
- **Build gotcha:** SPM resources produce `FloatNote_FloatNote.bundle` in `.build/release/`. `build.sh` copies every `.build/release/*.bundle` into the app's `Contents/Resources/` so `Bundle.module` resolves them — without this the board assets are missing at runtime.

## Terminal
- Shell lifecycle is owned by `TerminalSessions` (in `Terminal.swift`), NOT the SwiftUI view. A `TerminalSession` (LocalProcessTerminalView + child shell, started in a per-session `cwd`) is created lazily per terminal id via `session(for:cwd:)` and lives until `TerminalSessions.shared.close(id)` (called from `vm.closeTerminal`, i.e. the ✕ button). Use `existing(_:)` for a non-creating lookup. The shell's working directory is fixed at creation; `cwd` is ignored for an already-live session.
- **Tab system (one visible at a time)**: the panel is a tab bar (`TerminalPanel`) over `vm.terminalTabs: [TerminalTab]` (`{id, path, label}`) with `vm.activeTerminalId` selecting the visible one. Each chip is labelled by folder name, path on hover; `+` adds a tab at the active note's route (or HOME), ✕ closes one (activates a neighbor; last close hides the panel). There are no side-by-side columns and no per-column widths — `terminalWidth` is the single panel width. A toolbar **new-terminal** button (`plus.rectangle`, `newTerminalButton`) appears only while the panel is showing a terminal — before that the plain terminal toggle is the way in.
- **Panes bind to notes** (`TerminalTab.noteId`): several panes can share one project directory, so path alone stopped identifying "the note's terminal". `switchToRoute` prefers the pane bound to the active note, falls back to any pane on the path, and only then creates one (bound to the note that opened it). `bindTerminal(_:toNote:)` keeps it one note ↔ at most one pane — the newest binding wins. `selectTerminal` sends a bound pane straight back to its note, falling back to the folder's last note when unbound or the note is trashed. Without this, a second pane on a project was unreachable by routing and clicking its chip bounced you to pane #1.
- **Explicitly-added panes start a fresh Claude** (`TerminalTab.freshClaude` → `TerminalSession.freshClaude`): `addTerminal()` sets it so a second pane on the same project runs plain `claude` instead of `--continue`-ing into the conversation the first pane is already running. Route-created panes keep the normal `claudeLaunchCommand` decision.
- **Moving a note re-resolves its route**: both `moveTab(_:toFolder:)` and `moveTab(from:to:)` call `applyTerminalRouteForActiveNote()` when the moved note is active and its folder actually changed. Without it a note dragged into a project folder kept the old terminal until the next tab switch.
- **Project folders (note → terminal)**: a folder linked to a local directory (`Folder.localPath`) is a "project"; its notes inherit that directory as their terminal working dir. `vm.effectiveRoute(for:)` → `(path, label, source)` resolves in priority order: (1) the note's own `NoteTab.localPath` **override**; (2) the **nearest** ancestor folder (own folder included; `nearestLinkedFolder(startingAt:)`, trashed folders skipped, 64-hop cycle cap) with a non-empty `localPath`; (3) `.none`. Sub-projects therefore override their parent (**nearest wins** — the reverse of the old top-most rule). `terminalRoute(for:)` is a thin `(path,label)?` wrapper (nil = `.none`); the terminal-tab label is the project folder's name (inherited) or the path's last component (override). `vm.applyTerminalRouteForActiveNote()` runs on every `activeTabId` change (`switchTab`, `addTab`, launch): a route → `switchToRoute(path:label:)` which dedups by path (switch to the existing tab for that path, else create one) and auto-opens the panel; no route → hide the panel. **Setting a path**: folders via the sidebar context menu (**Link Local Folder… / Change… / Unlink** → `linkFolder`/`unlinkFolder`, native `NSOpenPanel`; linked folders show a 🔗 with the path on hover); a note's override via the **folder chip** in `FormatToolbar` (`folderChip` → `pickNoteFolder` → `setNoteFolderOverride`; ✕ → `clearNoteFolderOverride`; chip shows the dir's last component, full path on hover, accent=inherited / amber=own override / gray=unset). `localPath` persists in `~/.floatnote-folders.json` / `~/.floatnote-tabs.json` and syncs like `folderId`. One-time launch migration (`migrateTerminalPathNotesIfNeeded`, guarded by the `fn.projectFoldersMigrated` UserDefault) folds legacy "…terminal path" notes into their folder's `localPath`. Spec: `docs/superpowers/specs/2026-07-16-project-folders-design.md` (supersedes the 2026-06-18 folder-routed and 2026-07-07 ancestor-walk specs — the "terminal path" note convention is gone).
- **Route-gated toggle / no HOME fallback**: the toolbar terminal button is disabled + dimmed when the active note has no route (tooltip "Link a folder to use the terminal"); `toggleTerminal()`'s show branch is just `applyTerminalRouteForActiveNote()`. `showTerminal()` was removed — a routeless note can never open the panel (unpin restore included). HOME-rooted tabs exist only via `addTerminal()`'s fallback (`+`/Cmd+N from inside an open panel) or as legacy leftovers. Plan: `docs/superpowers/plans/2026-07-17-terminal-toggle-route-gate.md`.
- **Reverse routing (terminal → note)**: tapping a terminal chip calls `vm.selectTerminal(id)` (not a bare `activeTerminalId =` assignment), which sets the active terminal and then navigates to the related note. `folderForTerminalPath(_:)` reverse-maps the chip's path to the (non-trashed) folder whose `localPath` resolves to it; `noteToActivate(forTerminalFolder:)` picks the last note the user had open **anywhere in that folder's subtree** (`lastActiveNotePerFolder` — `switchTab` records subtree notes under the project folder via `nearestLinkedFolder` too), falling back to the folder's own first note. **No ping-pong**: the resulting note→terminal route dedups by path back to the same chip, so `activeTerminalId` doesn't re-fire. Chips whose path maps to no folder (e.g. a per-note override path, or the default HOME terminal) leave the active note untouched.
- **Focus follows the terminal**: whenever the panel is presented for a note (route on note switch/launch, chip tap, toolbar toggle, `+`/Cmd+N, folder link, unpin restore) `vm.focusActiveTerminal()` makes the terminal view first responder — retrying briefly (`focusTerminal(_:attempt:)`, 8×60ms) because the panel/session may still be mounting. Focus moves ONLY at these discrete events, so clicking into the editor keeps focus there until the next navigation. Carve-outs: `addTab` passes `applyTerminalRouteForActiveNote(focusTerminal: false)` + `focusEditor()` (new note → type the title), and the route's hide branch calls `focusEditor()` only when focus was stranded inside a terminal. The editor's custom block caret hides while the editor isn't first responder or the window isn't key (`isEditorFocused` flag set in `becomeFirstResponder`/`resignFirstResponder` + `didBecomeKey`/`didResignKey` window observers, gated in `updateCaretPosition()`) so an unfocused note never shows a caret. Spec: `docs/superpowers/specs/2026-07-17-terminal-focus-follows-route-design.md`.
- **SwiftTerm is a vendored fork** (`vendor/SwiftTerm`, gitignored; `FloatNote/Package.swift` uses `.package(path:)`). Run `./vendor-swiftterm.sh` once per machine and after changing `SWIFTTERM_VERSION` — it clones upstream v1.13.0 and applies `vendor/swiftterm-sticky-scroll.patch` (the tracked source of truth; regenerate with `git -C vendor/SwiftTerm format-patch -1 --stdout`). `build.sh` does NOT re-vendor. Four fixes, all things upstream can't do from the outside:
  - **Sticky scroll** — `scrollTo()` sets `Terminal.userScrolling`. `Terminal.scroll()` already honors that flag, but nothing upstream sets it (the *view* has a separate, identically-named property), so every byte of output yanked the viewport to the bottom.
  - **Selection survives trimming** — new `TerminalDelegate.linesTrimmed(source:count:)` (default no-op) fires after the buffer settles; `SelectionService.linesTrimmed(_:)` shifts `start`/`end`/`pivot`. Selection coords are line-ring indices, so without this the highlight walks down through the text as output streams and Cmd+C copies the wrong line. The handler must never re-enter the view's redraw (it sets `_active`, not `active`).
  - **`TerminalView.defaultScrollback`** — upstream hardcodes `TerminalOptions`' 500 lines and rebuilds options on every resize. `TerminalSessions.init` sets 20 000.
  - **Scroll-on-input** — `ensureCaretIsVisible()` now scrolls unconditionally. It used to scroll only when the caret was fully outside the viewport, so a partial scroll-back left you typing into an input box rendered off-screen.
- **Copy needs mouse reporting off**: `view.allowMouseReporting = false` in `TerminalSession.init`. With it on (SwiftTerm's default) every chunk of output runs `feedPrepare()` → `selection.active = false`, so text selected mid-stream is dropped and Cmd+C copies nothing. Claude Code is keyboard-driven, so nothing of value is lost.
- **Scroll-back pill**: `TerminalScrollPill` (in `Terminal.swift`) overlays the terminal bottom-trailing with "↓ N lines below" whenever the user is parked; click = jump to newest + resume following. Polls `linesBelowViewport` at 4Hz because SwiftTerm's `TerminalViewDelegate` callbacks aren't forwarded through `LocalProcessTerminalViewDelegate`.
- **Hiding ≠ killing**: `SwiftTermContainer.makeNSView` returns the cached session view and has no teardown, so hiding the panel (toolbar toggle / no-route navigation → `isTerminalVisible=false`) or any view remount never kills the shell. Do not move shell termination into `dismantleNSView`.
- **Panel always fits the window**: the panel is rendered at `min(terminalWidth, availablePanelWidth())` and the editor↔panel `TerminalResizeHandle` caps drags to `availablePanelWidth()` (window − sidebar − handles). Never render the panel wider than the window — chips get clipped.
- **Terminal-scoped shortcuts**: a local `NSEvent` key monitor in `AppDelegate` intercepts Cmd+N (new terminal) and Shift+Enter/Cmd+Enter (newline without submit) ONLY when `TerminalSessions.shared.id(containing: firstResponder)` matches; otherwise they keep default behavior. Cmd+W is swallowed app-wide (returns nil for every Cmd+W, regardless of focus) — it must never close the window, which would take the terminal panel with it; terminal tabs close only via the ✕ button or `exit`.
- **`exit` closes the pane**: `processTerminated` posts `.floatnoteTerminalExited` (object = session UUID), observed in `AppDelegate` → `vm.closeTerminal`. Intentional kills (restart / ✕) set `expectedTermination` on the session first so they don't self-close — keep that guard if you add new kill paths.
- **Claude auto-resume**: routed terminals auto-run `claude --continue` when `~/.claude/projects/<munged-cwd>` has session files; HOME and first-open projects run plain `claude`; a shell restart (`.floatnoteTerminalReset` — mechanism only, no UI trigger posts it yet) re-evaluates. Decision lives in `TerminalSession.claudeLaunchCommand` (`Terminal.swift`), computed at send time inside the existing 0.6s auto-run. Spec: `docs/superpowers/specs/2026-07-17-terminal-claude-auto-resume-design.md`.

## Claude Hook Notifications
- Claude Code sessions in FloatNote terminals produce native banners on turn end (`Stop`) and input requests (`Notification`). Pipeline: global hook in `~/.claude/settings.json` → `~/.claude/hooks/floatnote-notify.sh` (source: `docs/floatnote-claude-hook.sh`, reinstall on change) writes one JSON per event via temp+rename into the `~/.floatnote-claude-events/` spool; `vm.checkClaudeEvents()` consumes+deletes spool files, dropping events with no matching OPEN terminal tab (standardized-path compare of `cwd`) or older than 120s, then posts via `UNUserNotificationCenter` (title = tab label, body = "Claude finished working" / hook message).
- AppDelegate is the notification-center delegate: `willPresent` returns `[.banner, .sound]` (banners even while frontmost — "always notify"), `didReceive` (click) activates the app and re-resolves the tab **by path** → `selectTerminal` (chip + note navigation + terminal focus) + `isTerminalVisible = true`. Permission (`.alert/.sound`) requested at launch; the grant persists across rebuilds via the stable signing identity.
- **Delivery is watcher-driven**: `startClaudeEventWatcher()` puts a `DispatchSource` vnode watcher on the spool dir so events land the moment the hook writes one (the 2s timer still sweeps as a safety net — a watcher misses events if the dir is recreated). The hook also spools `last_assistant_message` (Claude's turn text, for hands-free voice) and early-exits on `stop_hook_active` so a re-entrant Stop can't double-spool.
- Debug: every posted banner logs `claude notification: <label> [<event>]` to `~/.floatnote-debug.log`, and every consumed event logs `claude event [<event>] → pane <label> turnText=<n>ch` (or `dropped — no open pane for <path>`); test by piping fake hook JSON into `~/.claude/hooks/floatnote-notify.sh` with a live tab's path as `cwd`. Spec: `docs/superpowers/specs/2026-07-17-claude-hook-notifications-design.md`.

## Hands-Free Voice (Claude Code)

Full speak → listen → submit loop against FloatNote's own terminal: Claude's turn is read aloud,
the mic stays open, and "send it" types the reply into the pane. Native port of
`claude-code-handsfree`. Spec: `docs/superpowers/specs/2026-08-06-handsfree-voice-design.md`.

- **Transport in is the existing hook spool**, not an HTTP server: `docs/floatnote-claude-hook.sh` adds `last_assistant_message` to each event, `checkClaudeEvents()` resolves `cwd` → `TerminalTab` and calls `HandsfreeManager.shared.handleTurnEnd(message:tab:)` on `Stop` / `handlePermissionPrompt(message:tab:)` on `Notification`. **Transport out is `TerminalSessions`** — `existing(activeTerminalId)?.view.send(txt:)`, the exact pane, no synthetic keystrokes and **no Accessibility permission**.
- **`HandsfreeManager`** (`Handsfree.swift`) owns the state machine and policy. Off by default. Every way in funnels through `vm.toggleHandsfree()` (route gate + one `dbg` line): **⌘⇧M** (an `NSEvent` monitor entry, so it works with focus inside a terminal), the **View ▸ Hands-Free Voice** menu item, and the toolbar `waveform.circle` button — deliberately NOT a `mic` glyph, because the editor's dictation button next door owns that and two identical mic icons is how it got pressed instead. **⌘.** stops the speech without disabling the session (`stopSpeakingFromKeyboard()`), falling through to its normal meaning when nothing is speaking. Enabling opens the terminal panel, clears `vm.wantsDictation`, asks for Speech authorization and starts listening.
- **The mic is NOT implied by the state.** It stays live through `.listening`, `.speaking` (barge-in) and `.processing` (so "stop" can interrupt a running Claude); only `.idle` releases it (mute, 120s silence, or recording). `micActive` tracks that separately.
- **`SpeechListener`** (in `VoiceEngine.swift`) is one `AVAudioEngine` tap feeding a *rolling series* of `SFSpeechAudioBufferRecognitionRequest`s: the engine runs for the whole session while recognition tasks are cycled (each ends on a pause, or is cut short by `restartTask()` after a command fires). `taskGen` drops callbacks from a cancelled task — without it, the final result of the task that carried "send it" submits the same sentence twice. On-device recognition is used when supported (local-only app, no ~1-minute server request cap).
  - **Input-device changes**: `AVAudioEngine` binds its input node at creation and never follows the default input device, so AirPods would leave recognition on the built-in mic. A CoreAudio `kAudioHardwarePropertyDefaultInputDevice` listener rebuilds a *fresh* engine — debounced 0.5s, on a private queue, only on a real device change. Do NOT drive this off `AVAudioEngineConfigurationChange` (main-thread rebuild loop → app freeze).
  - A runaway-restart guard (8 restarts / 5s) stops a permanently-failing recognizer from spinning.
- **Voice commands** — `VoiceEngine.parseCommand` is pure (no audio, no state): "…send it" (trailing, trigger stripped from the ORIGINAL text so casing survives), whole-utterance "stop" → ESC, "delete message", "cmd X" → `/X` (rest of the words become arguments), "focus window N" → `vm.selectTerminal`. Bare-utterance matching is deliberate: "don't stop the build" must not interrupt Claude. `parseQuickResponse` answers a permission prompt (yes→1, always→2, no→3, numbers) and is only consulted while `awaitingQuickResponse` (set by a `Notification` event, expires after 60s).
- **Enter is a separate write**: `submit()` sends the text, then `"\r"` 0.15s later. Claude Code's TUI reads raw input — a CR glued to the text can be swallowed as part of a paste instead of submitting it. (`"\n"` is the shell's line ending, not the TUI's Enter.)
- **Barge-in**: talking over playback stops it. Gated on playback having actually started (`VoiceEngine.speechStartedAt` + 0.6s — the state flips to `.speaking` while `say` is still rendering) and on an **echo filter**: the mic hears the speakers and there is no echo cancellation, so `VoiceEngine.echoOverlap(heard:spoken:)` ≥ 0.5 is treated as our own voice. Overlap, not equality — the recognizer never transcribes TTS back word-perfectly. Two words minimum, except a bare "stop", which during playback stops the *speech* only (the turn is already over, so it is not an interrupt).
- **What gets read is a digest, not the turn.** `.brief` (the default) speaks `VoiceEngine.brief`: the opening sentence plus the ask (the last question, or a closing "next step" line), capped at 45 words on a sentence boundary. Reading a real turn in `.full` measured 36s — and 122s for a long one — to deliver about two lines of news. `cleanForSpeech` also collapses absolute paths and `file.swift:12` refs to "the file" and drops markdown table rows.
- **A turn from a non-active pane is spoken prefixed with the pane label** ("floatnote: tests are passing") so concurrent agents stay distinguishable. Replies always go to the pane that is active at submit time.
- **The mic is exclusive**: `setEnabled` refuses while `vm.isRecording` and `startRecording()` calls `yieldToRecording()` (meeting capture wins). Editor dictation is a *different* mechanism (`NSTextInputContext startDictation:`) and must not run at the same time.
- **UI**: `HandsfreeBar` (`HandsfreeBar.swift`) sits under the terminal tab bar, only while enabled — waveform, live transcript (head-truncated so the newest words stay visible; rotating command hints when empty), reset, mute, a state-labelled primary capsule (Speak Now / Listening / Send It / Stop / Stop Claude) and a gear `NSMenu`. `HandsfreeMenuTarget` exists because `NSMenuItem` needs an ObjC target.
- **Settings** (all `UserDefaults`, domain `com.floatnote.app`): `fn.handsfreeResponseMode` (**brief** (default) / full / summary / notify), `fn.handsfreeVoiceId` (`"system"` = follow Spoken Content), `fn.handsfreeLocale` (recognition language, `"system"` = current locale), `fn.handsfreeBargeIn` (default **on**), `fn.handsfreeAutoSend` (submit after 3s of silence, default **off**).
- **Permissions**: `NSSpeechRecognitionUsageDescription` is in `Info.plist`; authorization is requested on first *use*, not at launch. Like Mic/Screen Recording, the grant survives rebuilds only because of the stable "FloatNote Dev" signing identity.
- Debug: `handsfree: …` and `tts: …` lines in `~/.floatnote-debug.log` (mic on/off, barge-in, send, ESC, quick response, pane resolution).

## Folders & Trash
- Folders live in `~/.floatnote-folders.json`: `{id, name, isExpanded, isTrashed?, parentId?}`
- Notes reference folders via `folderId` (UUID string). `null` = root.
- **Subfolders**: `Folder.parentId` (UUID, optional; `nil`/absent = root) nests folders arbitrarily deep. `SidebarFolderView` renders recursively (subfolders before notes, +16pt indent per level). Drag a folder header onto another folder to nest (`draggingFolderId` + `FolderDropDelegate`); drop on empty sidebar = move to root.
- **Folder reordering**: `FolderDropDelegate` splits a folder header row into three zones by `DropInfo.location.y` (row height measured into `SidebarFolderView.rowHeight` via `GeometryReader`): top 30% / bottom 30% = drop as previous/next **sibling** (`moveFolder(_:relativeTo:below:)`, accent insertion line, adopts the target's `parentId` so this is also how you promote a subfolder to root), middle 40% = nest inside (`moveFolder(_:toParent:)`, accent fill). Zones apply ONLY to a dragged folder — a dragged note still nests from any position. Sibling order is just the relative order of `vm.folders` (the sidebar filters by `parentId`, and `filter` preserves order), so reordering moves the array element and needs no new persisted field. Spec: `docs/superpowers/specs/2026-07-29-folder-reordering-design.md`. `moveFolder` rejects cycles (can't drop a folder onto itself/a descendant). MCP-created folders have no `parentId` (land at root); the MCP server round-trips folder objects so it preserves `parentId`.
- Trashing/deleting a folder **cascades** to its whole subtree (`descendantFolderIds`); the Trash section shows only subtree roots; restoring a subtree whose parent is gone/trashed reparents the root to top level.
- **Trash is virtual**, not a real folder:
  - Trashed folder → `Folder.isTrashed = true` (its notes keep their `folderId` so they restore as a group)
  - Loose-trashed note → `folderId = TRASH_FOLDER_ID` sentinel (`00000000-0000-0000-0000-000000000001`)
  - The Trash sentinel UUID must stay in sync between `App.swift` and `mcp-server.js`
- Sidebar renders a pinned Trash section at the bottom; trashed items have Restore + Delete Permanently in the context menu. No auto-purge.
- When mutating a nested `@Published` property of a `Folder`/`NoteTab` that the sidebar partitions on (e.g. `isTrashed`, `folderId`), reassign the parent VM array (`folders = folders` / `tabs = tabs`) so `@Published` re-fires and the sidebar repartitions.

## Default-Open Note
- On launch, the app restores the note that was open when it last quit: `fn.lastActiveNoteId` UserDefault, written by `activeTabId.didSet`. Fallback chain when that id is gone/trashed (or fresh install): first non-trashed note whose title contains "agentforce tasks" (case/whitespace-insensitive substring) → first non-trashed tab.
- `switchToFirstVisibleTab(excluding:)` keeps the agentforce-tasks preference (NOT last-open), so trashing the active note (or any other auto-switch path) lands back on the agentforce tasks note when it exists.

## Editor Features
- **Empty-note placeholder**: `BlockCaretTextView.draw(_:)` ghost-draws "Start writing…" (body-styled) when the document is empty — the note's title lives in the sidebar, not the document. Ghost color = `theme.editorTextNS` at 0.3 alpha (NOT a dynamic system color — those can resolve against the wrong appearance and go invisible). Redraws on emptiness flips in `didChangeText` and via `needsDisplay` in `updateNSView` (covers renames/tab switches).
- **Empty notes type as Body**: there is no title line in the document — the old ghost-"Title"/H1-arming (`isTitleLineActive`, `titleLineTypingAttributes`) was removed in v1.51.1. `onContentLoaded` and the delete-back-to-empty path in `didChangeText` both reset `typingAttributes` to `bodyLineTypingAttributes()` (AppKit drops typing attrs to stock defaults when the doc is cleared, so the re-pin is still required). No toolbar button has a persistent "active" state; all are hover-only.
- **Inline images**: paste (Cmd+V) or toolbar `photo` button → PNG in `~/.floatnote-images/<UUID>.png` (`ImageStore`, `Images.swift`) + an `ImageAttachment` (NSTextAttachment subclass carrying `imageId`/`displayWidth`) at the caret. **The Cocoa HTML exporter drops attachments**, so `extractHTML` swaps them for plain-text markers `⟦img:<uuid>:<width>⟧` on a COPY, and `htmlToAttributedString` swaps markers back on load (missing file → dimmed "missing image" text). Click an image → accent border + bottom-right drag handle (overlay subviews, caretView-style) → resize aspect-locked (min 60pt, max text width), undoable, saved via `didChangeText()`. Hard-delete/empty-trash cascades `ImageStore.deleteImages(inHTML:)`; inline deletion leaves the PNG (undo needs it — orphans tolerated). Spec: `docs/superpowers/specs/2026-07-22-image-attachments-design.md`.
- **Checkbox glyph (☑/☐) rendering**: SF Rounded has `☑` but not `☐` — Apple Symbols' fallback box has mismatched (thin, square) corners. `Tokens.Typography.checkboxAttributes(checked:)` / `styleCheckboxGlyph(_:range:checked:)` attach an `NSGlyphInfo` substituting SF Rounded's `□` (U+25A1) glyph for unchecked boxes so both states share identical rounded corners; the document character stays literal `☐` (badge counting, HTML persistence, MCP all key off it). `CheckboxTextStorage` (the `RichTextEditor`'s `NSTextStorage` subclass) re-pins the rounded font on every `☐` after `fixAttributes(in:)`, since stock attribute-fixing would otherwise swap in Apple Symbols and break the glyphInfo substitution (glyphInfo is only honored while the font attribute matches the font it was created with).
- **Toolbar**: Minimal plain-style buttons with hover highlights, flexible layout (all buttons visible at any width)
- **Font + size pickers**: `FontPicker` (family) and `BodySizePicker` (size) in the toolbar. Both persist to UserDefaults via `Tokens` (`fn.fontFamily` / `fn.bodyFontSize`) and call `vm.reloadActive()` to re-render the document live. All editor fonts route through `Tokens.Typography.editorFont(...)`, so the selected family/size applies everywhere (load normalization in `htmlToAttributedString`, typing attrs, headings). `"System"` = the built-in default; coordinator fonts are computed (not captured) so changes take effect without recreating the editor.
- **Undo/Redo**: All programmatic edits (checkbox toggle, bullet/checklist continuation, indent/outdent, format toolbar, drag-drop reorder) are undoable via snapshot-based undo registration
- **Tab/Shift-Tab**: Indent (4 spaces) / outdent selected lines or list items
- **List insert**: Pressing bullet/checklist at the beginning of an existing list line inserts a new line above and pushes the current line down
- **List continuation**: Enter on bullet/checklist lines continues with same prefix + indentation level
- **Hanging indent**: Wrapped text on list lines aligns after the prefix
- **Smart Home**: Cmd+Left jumps to after list prefix first, then to column 0 on second press
- **Smart Select**: Cmd+Shift+Left extends selection to after prefix, mirroring smart home
- **Smart Backspace**: Backspace at/inside a list prefix removes the entire prefix; Cmd+Backspace deletes to prefix boundary first, then removes prefix on second press
- **Move lines**: Option+Up/Down swaps lines, preserving caret position
- **Drag-to-reorder**: Click and drag list prefixes to reorder; blue insertion line shows drop target; dropped lines match target indentation
- **Dictation auto-restart**: When mic is enabled, dictation auto-restarts after system timeout or when app regains focus
- **Audio recording**: Record system audio (via ScreenCaptureKit) + microphone per tab, PCM-level merge, stored as .m4a in ~/.floatnote-recordings/
- **Transcription**: Deepgram-powered transcription with multi-language support (English, Turkish); 5-min timeout for large files
- **AI Summary**: OpenRouter-powered meeting summary (transcribe → summarize via AI); models: `openai/gpt-oss-120b:free` primary, `openai/gpt-oss-20b:free` fallback; outputs plain text with FloatNote-native formatting (• bullets, ☐ action items); auto-retry with model fallback on rate limits; API key at `~/.floatnote-openrouter.key`
- **Recording playback**: In-app audio player with seek, play/pause, stop; recordings linked to tabs

## Sidebar Unchecked-Item Badges
- Each sidebar note row (`SidebarNoteItemView`) shows a red `UncheckedBadge` pill (white number, `#ff3b30`) = count of unchecked `☐` glyphs in that note. Hidden when 0; counts >99 render as `99+`.
- Source of truth: `NoteTab.uncheckedCount` (`@Published`). `NoteTab.countUnchecked(in:)` counts `☐` chars; `recomputeUncheckedFromHTML()` runs it over the stored HTML (which keeps `☐` literal — no parsing needed).
- Recompute points: `NoteTab.from` (load + external merge of non-active tabs), the external-change merge for the active tab, and — for **live** updates — the editor coordinator's `textDidChange`, which counts the live `NSTextStorage.string` and passes it to `vm.textDidChange(html:length:uncheckedCount:)` → `activeTab?.uncheckedCount`. Checkbox toggles route through `didChangeText()` → `textDidChange`, so the badge drops the instant a box is checked, before any save. Spec: `docs/superpowers/specs/2026-06-18-unchecked-badges-and-terminal-note-nav-design.md`.
